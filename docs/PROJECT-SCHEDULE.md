# Project Completion Schedule

**Model:** Incremental development with short review cycles  
**Proposed window:** 2 November 2026 - 15 January 2027  
**Owner:** Student developer  
**Review points:** End of each increment; dates may be adjusted with instructor approval.

| Week | Dates | Planned work | Milestone / evidence |
|---|---|---|---|
| W1 | Nov 2-8, 2026 | Requirements, scope, stakeholders, acceptance criteria | M1: SRS / scope baseline |
| W2 | Nov 9-15 | DFD, use case, activity, ERD, class and object diagrams; initial architecture | M2: design baseline |
| W3 | Nov 16-22 | Dataset review notes, UI polish, directory logic checks | Directory/data quality review |
| W4 | Nov 23-29 | Search, filters, profile cards and responsive states | M3: search demo |
| W5 | Nov 30-Dec 6 | Booking input, date rules, patient validation and local record format | Booking workflow review |
| W6 | Dec 7-13 | Serial/reference allocation, slip/status flow, baseline regression | M4: booking increment |
| W7 | Dec 14-20 | Demo admin/export review, seven-class OOP interface, diagram/code traceability | OOP and admin review |
| W8 | Dec 21-27 | Functional, negative, capacity, persistence, responsive tests | M5: test release candidate |
| W9 | Dec 28-Jan 3, 2027 | Risk/privacy review, defect fixes, documentation updates | Final review feedback closed or logged |
| W10 | Jan 4-10, 2027 | Resolve final review feedback, perform a clean clone/run test, verify diagrams and deployment workflow | Final review / release candidate |
| W11 | Jan 11-15, 2027 | Finalize README and metadata, compile/review PDF, package repository and prepare course submission | M6: final delivery |

## Dependencies

1. Requirements and boundaries inform the diagrams.
2. The class diagram is baselined before completing the OOP interface.
3. Booking tests require the directory data and serial rules to be stable.
4. Final packaging depends on completed tests, checked PDF output and accurate README instructions.

## Exit criteria

The project is ready for submission when the proposal PDF and LaTeX source are included, all six required diagram types are available as editable sources and renderings, the OOP page demonstrates at least five matching classes, local file paths resolve, automated checks pass, known limits are disclosed, and the student has completed the manual browser test record.
